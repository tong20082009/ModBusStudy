# ModBusStudy 学习路线与实现计划

> **本项目的第一目标不是"做完软件"，而是"学会开发上位机软件"。**
> 每一步都遵循同样的节奏：**先想清楚"为什么"，再动手做"怎么做"，最后用"完成标志"自检**。
>
> 每个步骤都很小，建议一次只做一个步骤；做完一个、想通了，再进入下一个。

---

## 一、项目要做什么（读 README 得到的结论）

做一个"温控设备监控系统"（上位机，跑在电脑上），去监控一个模拟的"温控箱"（下位机，模拟出来的设备）。

设备对外暴露 4 个"寄存器"（可以理解为设备身上的"数据接口"）：

| 地址 | 含义 | 类型 | 说明 |
| ---- | ---- | ---- | ---- |
| 40001 | 当前温度 | float | 保持寄存器，设备"上报"给上位机读 |
| 40002 | 目标温度 | float | 保持寄存器，上位机可以写（设定目标） |
| 00001 | 加热状态 | bool | 线圈，设备当前是否在加热 |
| 00002 | 启动按钮 | bool | 线圈，上位机写入"1"表示启动 |

软件界面要包含：

- 标题：温控设备监控系统
- 当前温度、目标温度、加热状态 三块实时显示
- 【启动】【停止】两个控制按钮
- 实时温度曲线
- 报警记录列表

> 注意：设备是**模拟**的，所以一开始根本不需要真实网络通信——先造一个"假设备"（C# 类），
> 后面阶段再把"假设备"换成真实的 ModBus 通信。**先学会让数据在程序内部流动，再学数据怎么通过网络流动。**

---

## 二、总体学习思路

整个学习过程可以概括为一条主线，由浅入深：

```mermaid
flowchart LR
    A[阶段0<br/>认识项目骨架] --> B[阶段1<br/>搭建静态界面]
    B --> C[阶段2<br/>创建模拟设备]
    C --> D[阶段3<br/>界面数据流]
    D --> E[阶段4<br/>实时曲线]
    E --> F[阶段5<br/>报警记录]
    F --> G[阶段6<br/>真实ModBus通信]
    G --> H[阶段7<br/>工程化收尾]
```

- **阶段 0~1**：先把"壳"搭起来（认识工程、画界面）——建立信心，看到东西。
- **阶段 2~3**：把"芯"造出来（模拟设备 + 界面数据流）——理解上位机最核心的"读数据、下指令"。
- **阶段 4~5**：让软件更像"监控系统"（曲线、报警）——理解实时监控场景的常见需求。
- **阶段 6**：真正的灵魂——用 ModBus 协议通信，把模拟设备换成"走网络"的真实通信（可选 RTU 串口）。
- **阶段 7**：工程化收尾（分层、日志、发布）——让代码能长期维护、能上线。

> 教学原则：**每阶段先实现"能跑的简单版"，再谈"优雅"。** 不要一上来就追求架构，那会淹没学习重点。

## 三、分阶段步骤（详细）

---

### 阶段 0：认识项目骨架（预计 1 次，约 30 分钟）

**目的**：搞清楚"这个项目现在是什么样、文件都是干嘛的、怎么跑起来"，为后面所有步骤打底。

#### 步骤 0.1 理解"上位机 / 下位机 / ModBus"三个词

- **目标（学什么）**：建立上位机开发的世界观。
- **做什么**：
  1. 用自己的话解释：上位机 = 电脑上的软件（本项目的 WinForms 程序）；下位机 = 设备（本项目的温控箱）；ModBus = 两者通信时使用的"语言/协议"。
  2. 再对着 README 的寄存器表，理解"上位机通过地址读写设备数据"这个动作。
- **完成标志**：能不看文档，向别人讲清楚这三个词和它们的关系。

#### 步骤 0.2 认识 WinForms 项目的四个文件

- **目标（学什么）**：搞清一个 WinForms 工程的最小组成，破除"文件多=复杂"的恐惧。
- **做什么**：逐个打开并阅读（只读不写）：
  - `Program.cs` —— 程序入口，负责"启动窗体"。
  - `MainForm.cs` —— 窗体的"逻辑部分"（你以后写代码的地方）。
  - `MainForm.Designer.cs` —— 窗体的"界面描述"（可视化设计器自动生成）。
  - `ModBusStudy.csproj` —— 工程配置（目标框架、引用等）。
- **完成标志**：能说出每个文件各自负责什么。

#### 步骤 0.3 把空项目跑起来

- **目标（学什么）**：跑通"改代码 → 运行 → 看到窗口"这个基本循环，这是所有后续步骤的节奏。
- **做什么**：按 F5 运行，看到一个空窗口；试着改一下窗体标题（`MainForm.Designer.cs` 里的 `Text`），再运行看效果。
- **完成标志**：能独立运行程序、改一个属性、看到变化。

---

### 阶段 1：搭建静态界面（预计 2~3 次）

**目的**：做出一个"不会动但长得对"的界面。界面是上位机的门面，也是后面所有数据展示的容器。

> 可以类比 ASP.NET：Designer 拖控件 ≈ 用可视化工具写 Razor；手动改 Designer.cs ≈ 手写 HTML。

#### 步骤 1.1 先画界面草图（不写代码！）

- **目标（学什么）**：学会"先设计、后编码"的工程习惯。
- **做什么**：在纸上（或画图软件）画出 README 里的界面：标题、温度区、状态区、按钮、曲线区、报警区。给每个区域标注"用什么控件合适"。
- **完成标志**：手里有一张布局草图，并且知道每个区域大概用什么控件（不确定也没关系，下一步验证）。

#### 步骤 1.2 认识常用控件

- **目标（学什么）**：认识并理解 6 个最常用控件：`Label`（显示文本）、`Button`（按钮）、`GroupBox`（分组框）、`TextBox`（输入框）、`ListView`/`DataGridView`（列表，报警区用）、`Chart`（曲线，阶段 4 用）。
- **做什么**：打开工具箱，把控件拖到窗体上，观察"属性窗口"里的常用属性（`Text`、`Name`、`Font`、`ForeColor`、`BackColor`）。
- **完成标志**：看到属性就知道它是干嘛的（比如 `Name` 是给控件起名，`Text` 是显示的文字）。

#### 步骤 1.3 用 Designer 搭出主界面

- **目标（学什么）**：掌握可视化设计器的基本操作。
- **做什么**：按草图把标题、三个显示区（当前温度 / 目标温度 / 状态）、【启动】【停止】按钮、报警列表拖出来；给每个控件起一个有意义的名字（例如 `lblCurrentTemp`、`btnStart`），**注意命名规范：`lbl`/`btn` 前缀 + 含义**。
- **完成标志**：界面静态效果和草图一致；运行后窗口显示正确。
- **💡 提示**：做完这一步，回去读一眼 `MainForm.Designer.cs`，你会发现"拖出来的界面"其实全是 C# 代码——这就是 WinForms 的本质：**界面 = 代码**。

#### 步骤 1.4 布局美化与自适应

- **目标（学什么）**：理解 `Anchor`（锚定）和 `Dock`（停靠）——为什么窗口拉伸时控件要跟着走。
- **做什么**：给按钮、显示区设置合适的 `Anchor`，让窗口拉伸时布局不乱；调整字体、颜色，让界面更像"监控软件"。
- **完成标志**：窗口任意拉伸，布局都不乱；界面美观度自己满意。

> **阶段 1 回顾**：现在界面是"死的"。下一个阶段给它造一个"活的"设备。

---

### 阶段 2：创建模拟设备（预计 2 次）

**目的**：在程序里造一个"会呼吸"的假设备。这是整个项目最核心的业务对象，也是理解"寄存器"的第一步。

> 可以类比 ASP.NET：设备类 ≈ 一个 Service 类 / 一个实体模型，UI 不直接碰数据，而是通过它。

#### 步骤 2.1 把寄存器表翻译成 C# 属性

- **目标（学什么）**：理解"设备地址 ↔ 程序属性"的映射关系。
- **做什么**：新建 `TemperatureDevice.cs`，先只写 4 个属性：
  - `CurrentTemperature`（对应 40001，当前温度）
  - `TargetTemperature`（对应 40002，目标温度）
  - `IsHeating`（对应 00001，加热状态）
  - `IsStarted`（对应 00002，启动状态）
  - 每个属性**加注释**（按代码风格要求）。
- **完成标志**：设备类有 4 个带注释的属性，并在类上写好"这个类是什么、为什么这么设计"的详细注释。

#### 步骤 2.2 实现设备的"呼吸"逻辑

- **目标（学什么）**：理解设备不是"一堆数据"，而是"有内部逻辑的活物"。
- **做什么**：给设备类加一个 `Tick()` 方法（每次调用模拟过了一小段时间）：
  - 已启动且温度 < 目标温度 → 温度缓慢上升（加热），`IsHeating = true`；
  - 温度 ≥ 目标温度 → 停止加热，`IsHeating = false`；
  - 未启动 → 温度缓慢下降（散热），`IsHeating = false`。
  - 再加 `Start()` / `Stop()` 方法，修改 `IsStarted`。
- **完成标志**：能用一句话讲清楚"设备在什么情况下升温、什么情况下降温"。

#### 步骤 2.3 用控制台测试设备（临时）

- **目标（学什么）**：学会"先单独测逻辑，再接界面"的开发习惯——上位机开发中，通信逻辑和界面逻辑一定要能分开验证。
- **做什么**：临时在 `Program.cs` 里写一个循环，不断调用 `Tick()` 并打印温度，观察温度变化是否符合预期；测试完再还原 `Program.cs`。
- **完成标志**：控制台里能看到温度从 25℃ 慢慢升到目标温度，然后保持稳定。

> **阶段 2 回顾**：现在程序里有一个"活的设备"了，但界面还看不见它。下一步把两者连起来。

---

### 阶段 3：让界面活起来（数据流）（预计 2~3 次）

**目的**：打通上位机最核心的数据流——**定时读设备（上行）+ 按钮下指令（下行）**。

#### 步骤 3.1 认识 Timer 控件（轮询）

- **目标（学什么）**：理解上位机"持续监视"设备的机制——**轮询**（每隔一小段时间主动读一次），这也是后面 ModBus 通信的基础。
- **做什么**：从工具箱拖一个 `Timer`，设置 `Interval = 500`（每 0.5 秒一次），在它的 `Tick` 事件里调用 `device.Tick()`，并把 `CurrentTemperature` 显示到界面。
- **完成标志**：界面上的温度数字每 0.5 秒变化一次。

> **和 ASP.NET 对照**：Web 里服务端"推"数据常用 SignalR；上位机更常见的是"定时轮询"。理解两者的取舍（实时性 vs 简单可靠）。

#### 步骤 3.2 显示设备完整状态

- **目标（学什么）**：学会"设备状态 → 界面显示"的映射，包括数值格式化（`25.6℃`）。
- **做什么**：在 Timer 里把当前温度、目标温度、加热状态都显示出来；温度显示保留 1 位小数；加热中显示"加热中"，否则显示"待机"。
- **完成标志**：三个区域都能正确反映设备状态。

#### 步骤 3.3 启动 / 停止按钮（下行指令）

- **目标（学什么）**：理解上位机的另一条链路——**界面事件 → 调用设备方法 → 设备状态变化 → 界面再读回来**。
- **做什么**：给【启动】双击添加 `Click` 事件处理器，里面调用 `device.Start()`；【停止】同理调用 `device.Stop()`。
- **完成标志**：点【启动】后温度开始上升、状态变"加热中"；点【停止】后温度回落。

#### 步骤 3.4 认识 UI 线程

- **目标（学什么）**：理解"为什么 Timer 直接改控件没问题，但以后做真实通信时不能随便改控件"——所有控件只能在 UI 线程上操作，Timer 恰好跑在 UI 线程上。
- **做什么**：查阅资料理解"UI 线程 / 跨线程访问控件 / `Invoke`"这三个概念（知道存在即可，不一定要写代码）。
- **完成标志**：能解释"阶段 6 做异步通信时，为什么更新控件前要先 `Invoke` 回 UI 线程"。

> **阶段 3 回顾**：现在界面和设备"连起来了"。下一个阶段解决"怎么把数据变成曲线"。

---

### 阶段 4：实时曲线（预计 2 次）

**目的**：做出"实时曲线"。这是监控类上位机的招牌功能，核心是**数据采集 + 缓存 + 绘图**。

#### 步骤 4.1 引入 Chart 控件

- **目标（学什么）**：学会引入第三方/扩展控件（WinForms 自带的图表控件需要装一个 NuGet 包）。
- **做什么**：通过 NuGet 安装 `System.Windows.Forms.DataVisualization` 包，把 `Chart` 控件拖到窗体。
- **完成标志**：窗体上出现一个能显示坐标轴的图表控件。

#### 步骤 4.2 数据采集与缓存

- **目标（学什么）**：理解"曲线画的是历史数据"——需要先把历史数据存下来。
- **做什么**：在设备类或窗体里维护一个 `List<float>`（或 `List<DateTime>` + 温度），每次 Timer 把当前温度追加进去。
- **完成标志**：能调试看到列表里数据在持续增长。

#### 步骤 4.3 画出滚动曲线

- **目标（学什么）**：理解实时曲线的两个关键：**只画最近 N 个点**、**超出的旧点丢弃**（否则内存和画面都会爆炸）。
- **做什么**：把缓存数据画到 Chart；当点数超过上限（如 300 个）时移除最旧的点，并调整 X 轴范围让曲线"滚动"。
- **完成标志**：看到一条随温度变化的实时曲线，且只显示最近一段。

#### 步骤 4.4 曲线美化

- **目标（学什么）**：认识 Chart 的系列（Series）、坐标轴（ChartArea）配置。
- **做什么**：设置曲线颜色、粗细、图例名称（如"当前温度"），设置 Y 轴合理范围。
- **完成标志**：曲线清晰美观，有图例，坐标可读。

> **阶段 4 回顾**：现在软件已经像个"监控系统"了。下一个阶段加"报警"。

---

### 阶段 5：报警与记录（预计 2 次）

**目的**：实现报警检测和记录展示。这是监控系统的"眼睛"——让软件发现问题、留下证据。

#### 步骤 5.1 定义报警规则

- **目标（学什么）**：学会把"业务规则"翻译成代码。这是和 ASP.NET 里"业务逻辑/校验"最像的部分。
- **做什么**：先定 1~2 条简单规则，例如：
  - 温度超过目标温度 5℃（过冲报警）；
  - 启动后 2 分钟仍未达到目标温度（升温超时报警）。
- **完成标志**：能用一句话说清每条规则的触发条件。

#### 步骤 5.2 实现报警检测（边沿检测）

- **目标（学什么）**：理解"报警只触发一次"的**边沿检测**——不能条件一满足就狂加记录，要记录"上一次是否已报警"。
- **做什么**：在 Timer 里做检测，用一个 bool 标志记住"当前是否处于报警中"，只在"从正常变报警"的那一刻记录一次。
- **完成标志**：报警条件持续满足时，只产生一条报警记录。

#### 步骤 5.3 报警列表显示

- **目标（学什么）**：认识 `ListView` 或 `DataGridView`，学会往列表里动态加行。
- **做什么**：报警发生时，在列表里加一行（时间 + 报警内容）；报警解除时，把对应行标记为"已恢复"（或用第二列显示状态）。
- **完成标志**：报警列表能实时出现记录，并且能看出"发生/恢复"的状态。

> **阶段 5 回顾**：到这里，用"假设备"能实现的全部功能都做完了。下一步是重头戏——把假设备换成真的 ModBus 通信。

---

### 阶段 6：真实的 ModBus 通信（预计 4~5 次）

**目的**：上位机的灵魂——**通过网络和真正的设备通信**。这是整个项目最有价值、也最能体现"上位机"本质的阶段。

> 这一阶段依然不需要真实硬件：先用 NModbus 库在**同一台电脑上**搭一个"ModBus 服务器"扮演温控箱，你的程序作为"ModBus 客户端"去连它。效果和真设备完全一样。

#### 步骤 6.1 深入理解 ModBus 协议

- **目标（学什么）**：真正理解协议本身——寄存器类型、功能码、报文格式。
- **做什么**：
  1. 搞清两类数据：**保持寄存器**（Holding Register，可读可写，用功能码 03/06）和**线圈**（Coil，可读可写，用功能码 01/05）；
  2. 搞清"float 占 2 个寄存器"这个细节（40001 是 float，其实占 40001~40002 两个寄存器）——并思考：README 里 40001/40002 都是 float，地址是不是有点重叠？这就是真实世界协议文档常见的"坑"，值得研究；
  3. 看一个"读保持寄存器"请求/响应报文的十六进制例子，逐字节解释。
- **完成标志**：能自己画出"读 40001"的请求报文和响应报文。

#### 步骤 6.2 搭建 ModBus 模拟服务器（扮演温控箱）

- **目标（学什么）**：理解"下位机"那一侧在做什么——这对理解整个通信过程非常重要。
- **做什么**：安装 `NModbus` NuGet 包，写一个小控制台程序：启动一个 ModBus TCP 服务器，把寄存器数据（温度、线圈）挂在服务器上，让温度值持续变化。
- **完成标志**：用 Modbus 调试工具（如 Modbus Poll / 自己写客户端）能连上服务器、读到变化的温度。

#### 步骤 6.3 封装通信层（接口解耦）

- **目标（学什么）**：学会"面向接口编程"——这是上位机架构的核心思想，也是从"能跑"到"专业"的分水岭。
- **做什么**：
  1. 定义一个 `IDevice` 接口（`ReadCurrentTemperature()`、`ReadTargetTemperature()`、`ReadIsHeating()`、`WriteStart(bool)` 等）；
  2. 让原来的 `TemperatureDevice` 实现它（变成"模拟实现"）；
  3. 新建 `ModBusDevice` 类实现同一个接口（内部用 NModbus 客户端去读服务器）；
  4. 让 UI 只依赖 `IDevice`，通过一行代码切换"用模拟设备还是用真通信"。
- **完成标志**：UI 代码里不出现任何 NModbus 相关代码；改一行代码就能在"模拟 / 真实通信"间切换。

#### 步骤 6.4 异步通信（界面不卡顿）

- **目标（学什么）**：理解为什么网络读写不能阻塞 UI 线程，学会 `async/await`。
- **做什么**：把 `ModBusDevice` 的读写方法改成 `async`；在 UI 里用 `await` 调用，再配合 `Invoke`/`BeginInvoke` 回 UI 线程更新控件；加上超时和异常处理（断线时界面不能卡死）。
- **完成标志**：拔掉网线（或关掉服务器）时，界面不卡死，而且能提示"通信失败"。

#### 步骤 6.5 连接参数配置化

- **目标（学什么）**：理解"IP / 端口 / 从站地址"这些连接参数的意义，学会配置化。
- **做什么**：把 IP、端口、从站 ID 放到配置文件（或加一个简单的设置界面），程序启动时读取。
- **完成标志**：改配置文件就能连到不同的设备，不用改代码。

> **阶段 6 回顾**：到这里，你已经做完了真正的"上位机开发核心"——协议理解 + 通信封装 + 异步 + 配置。值得庆祝。

### 阶段 7：工程化收尾（预计 2~3 次）

**目的**：让项目"能长期维护、能发布给用户用"。这一步体现的是"开发规范"而非新功能。

#### 步骤 7.1 分层重构

- **目标（学什么）**：理解上位机的经典分层：**界面层（UI）→ 业务逻辑层（采集/控制/报警）→ 设备通信层**，并体会"职责单一"。
- **做什么**：按这个思路整理目录结构（如 `UI/`、`Device/`、`Core/`），把 Timer 采集、报警检测从窗体里挪到业务类中，窗体只负责"显示和转发"。
- **完成标志**：能画出项目分层图，并说清每层只干什么、依赖谁。

#### 步骤 7.2 加日志

- **目标（学什么）**：理解"日志"是生产环境排障的第一手段，学会用现成日志库（如 NLog / Serilog）。
- **做什么**：记录通信请求、错误、报警到日志文件（带时间戳）；模拟一次断线，靠日志定位问题。
- **完成标志**：出问题时，能通过日志文件还原发生了什么。

#### 步骤 7.3 发布

- **目标（学什么）**：理解发布与调试的区别，学会发布单文件 exe。
- **做什么**：用 `dotnet publish` 发布为单文件 exe（`SelfContained` 或框架依赖），拷到别的电脑测试运行。
- **完成标志**：不装开发环境也能运行这个软件。

> **可选进阶方向**（做完主线后）：ModBus RTU（串口）、WPF 重做界面、MVVM、报警历史存数据库、多设备同时监控。

## 四、ASP.NET 背景知识对照表

你在学习过程中会不断遇到"这个我好像在 Web 里见过"。这张表帮你把旧知识迁移过来：

| ASP.NET 概念 | 上位机对应 | 说明 |
| ---- | ---- | ---- |
| Razor / HTML 页面 | WinForms 窗体（Designer） | 都是"描述界面"，一个拖控件、一个写标签 |
| Controller / Action | 事件处理器（Click/Tick） | 都是"接到请求后执行逻辑" |
| EF Core / Service 层 | 设备类 / 通信层 | 都是把"数据来源"封装起来，UI 不直接碰 |

| ILogger | NLog / Serilog | 都是打日志 |

## 五、贯穿全程的代码风格要求（必须遵守 `docs/代码风格.md`）

每写一个类 / 方法 / 字段，都按下面自查：

1. **类上**：写详细注释——这个类的作用、为什么这么设计、基于哪些考虑。这是"教学"的核心，注释是写给未来的自己看的。
2. **方法上**：注释要**简短**——一句话说清"干什么"，不写长篇大论（避免打断阅读思路）。
3. **字段 / 属性上**：写必要的注释，说明它代表什么。
4. 面向"小白读者"：命名清晰（`CurrentTemperature` 而不是 `ct`）、代码直白、不炫技。

> 每完成一个步骤，都花 1 分钟回头检查自己写的代码注释是否符合这四条。

## 六、给学习者（你自己）的建议

1. **一次只做一步**：别急着跳阶段，每一步的"完成标志"都达到再前进。
2. **先复述再动手**：动手前，先用自己的话把"这一步要学什么"说出来，说不清就先不写代码。
3. **错误是最好的老师**：遇到报错不要慌，把报错信息读三遍，往往答案就在里面；解决一个 bug 后，想想"为什么会这样"。
4. **每阶段回顾**：每完成一个阶段，用两三句话总结"我学会了什么"，可以写在这个文件下面。
5. **可以随时停下来**：本项目没有交付压力，卡住了就休息或回来查资料，理解永远优先于进度。
